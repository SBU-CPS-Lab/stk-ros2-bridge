# MATLAB / Simulink Setup

## Version matching -- read this first

| MATLAB release | ROS 2 distro supported | Use with |
|---|---|---|
| R2023b | Humble | **Recommended.** |
| R2024a | Humble | Also fine. |
| Anything else | Not Humble | **Will not work reliably.** A mismatched distro produces custom-message failures that look like network problems -- see [06_troubleshooting.md](06_troubleshooting.md). |

Confirm your release's supported distro against MathWorks' current ROS
Toolbox System Requirements page before proceeding; that page is the
authoritative source and may have changed since this was written.

## 1. Confirm ROS Toolbox is installed

```matlab
ver('ros')
```

## 2. Install Visual Studio Build Tools (Windows, if not already present)

`ros2genmsg` compiles C++ against MATLAB's bundled ROS 2 client
libraries. Install **Visual Studio Build Tools** with the "Desktop
development with C++" workload. This is easy to miss because the
failure, if you skip it, happens deep inside message generation with a
compiler-not-found error that doesn't mention Visual Studio by name.

## 3. Run `setup_stk_ros`

```matlab
cd path\to\stk_ros2_ws\src\stk_matlab
setup_stk_ros()
```

This adds `+stkros` to your path, runs `ros2genmsg` on `stk_msgs` (first
run only; pass `'Rebuild', true` to force), and checks the ROS 2 network
is reachable.

## 4. Set `ROS_DOMAIN_ID` if needed

On a single-host (T1) setup this is usually unnecessary. On a split
topology (bridge on Linux, MATLAB on Windows -- T2/T3), set it to match
before starting MATLAB:

```powershell
$env:ROS_DOMAIN_ID = "42"
matlab
```

## 5. Try the examples

With `stk_bridge_mock.launch.py` running (see
[01_installation_windows.md](01_installation_windows.md) step 6):

```matlab
run examples/example_01_read_telemetry.m
```

Then, once that works:

```matlab
run examples/example_02_closed_loop_attitude.m
run examples/example_03_lockstep_stepping.m
```

## 6. Simulink

```matlab
cd simulink
stk_bus_definitions()      % optional: creates Simulink.Bus objects for Bus-typed signals
build_twin_template()      % generates stk_twin_template.slx
open_system('stk_twin_template')
```

Replace the `ControlLaw_PLACEHOLDER` block with your actual ADCS logic.
See `build_twin_template.m`'s header comment for why the model is
generated by script rather than checked in as a binary `.slx`.

## use_sim_time in Simulink

The ROS 2 Current Time block must read from `/clock`, not wall time,
whenever the bridge is in `lockstep` or `paced` mode. `build_twin_template`
attempts to set this automatically (`ROSTimeSource: 'ROSClock'`); verify
it under Simulation > Model Configuration Parameters > ROS 2 if the
model was hand-built instead. See
[05_time_synchronization.md](05_time_synchronization.md).
